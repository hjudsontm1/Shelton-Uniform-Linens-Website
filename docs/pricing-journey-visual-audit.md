# Pricing Journey Visual-Layer Audit

Audit date: 2026-07-12

The configuration, reducer-like state controller, dependency cleanup, persistence, vector renderer, development pricing interface, payload builder, and automated test structure are sound enough to preserve. The active `orb-story` visual override does not meet the requested art direction and must not be treated as a finished 5/5.

| Current component | Classification | Decision |
| --- | --- | --- |
| Central journey state and chapter completion | Keep | Preserve the state model, versioned session restore, compatible-answer retention, and explicit completion order. |
| Operation, goods, scale, finish, specialty, and ownership configuration | Keep | Continue using centralized branch data; do not add branch conditions to event handlers. |
| Development pricing rules | Keep | Preserve the deterministic replaceable interface and visible development warning. |
| Vector-goods renderer | Keep, refine presentation | Retain the shared SVG primitives and selected-only narrowing; improve their scale, spacing, and surrounding composition through CSS. |
| Exact-quote payload shell | Keep | Preserve all estimator answers, collect only missing contact details, and remain local/no-submit. |
| Landing headline layered over orb | Remove | Directly violates the required visual separation and makes the orb behave like a background. |
| Oversized glossy orb | Redesign | Replace with a contained matte woven service seal occupying roughly one quarter of the useful desktop viewport. |
| Separate circular BEGIN object | Redesign | Convert to a restrained woven tab aligned with the seal seam; no second orb/button. |
| Sticky numbered progress navigation | Remove | It reads as a standard progress bar. Program continuity will come from the chapter thread and completed notes in document flow. |
| Completed chapter blocks at roughly 13rem | Redesign | Condense to 72-104px open notes with answer and Edit action. |
| Two-column numbered operation list | Redesign | Replace with a horizontally discoverable editorial focus rail with roving radio semantics and a contextual operation scene. |
| Goods answer grid | Redesign | Keep semantic multi-select controls but present them as an open text rail below the physical goods scene, without filled tiles. |

| Ownership rows | Redesign | Preserve plain-language radio choices while presenting them as three/four open service paths instead of card-like rows. |
| Location field | Keep, refine | ZIP/city-only behavior is correct; strip remaining panel treatment and resolve the thread into a small route marker. |
| Review answer grid | Redesign | Preserve editable answers, but use one assembled composition with concise atelier-note lines rather than dashboard cells. |
| Result composition | Redesign | Make the parchment service dossier the single major contained surface and move range, rhythm, model, comparison, and factors into that physical document. |
| Page-wide gradient bands and chapter dividers | Remove/refine | Use one continuous near-black navy canvas with localized object light and no stitched section backgrounds. |

## Immediate Failing Criteria

- Landing copy overlaps the orb.
- Orb is oversized, glossy, and reads more like a tech sphere than woven textile.
- BEGIN is a second circular object.
- Sticky numbered navigation is a conventional progress rail.
- Operation is a numbered two-column list.
- Completed chapters exceed the requested condensed height.
- Goods and finish controls still read as rectangular grids.
- Result range is a paper card beside the result rather than a resolved service dossier containing the recommendation.

These defects reopened the final visual checkpoint. Existing automated passes remained useful for regression protection but did not justify the previous visual 5/5 score.

## Final Disposition

All immediate failures above were corrected in the memo-reconciliation pass:

- Copy and seal are separate; the seal is contained, matte, and woven.
- Begin is one integrated woven tab.
- The active progress rail and empty program summary are removed.
- Operation, Goods, Finish, and specialty controls use open editorial rails.
- Completed notes fit the compact target.
- Review is an assembled scene with open note lines.
- The final parchment dossier contains the complete result and is the only major contained surface.
- Scale, Ownership, and Location were tightened after screenshot review to remove excess laptop-height dead space.

Current evidence is mapped in `pricing-journey-final-review.md`; the final evidence-based score is recorded in `pricing-journey-rubric.md`.
